# Project Scaffold Prompt — Gradle Multi-Project Minecraft Plugin (GitLab)

Use this file as the single prompt when starting a new Minecraft plugin project and publishing to **GitLab Maven**. It describes every build file, directory, and dependency-scoping rule so an LLM or a developer can scaffold the whole repo from scratch.

## 0. Directory Layout (source of truth)

```
<root>/                              <- no source of its own; build orchestration only
├── gradle/
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties   <- Gradle version, distribution URL
├── gradlew                            <- executable wrapper script
├── gradlew.bat
├── settings.gradle                    <- root project name + every `include`
├── build.gradle                       <- root: applies the convention plugin
├── gradle.properties                  <- project identity + version
├── .gitignore
├── README.md
├── AGENTS.md
├── api/                               <- leaf: pure Java contracts, `java-library`
│   └── src/main/java/<group>/<project>/api/...
├── common/                            <- data layer, depends `compileOnly` on api
│   └── src/main/java/<group>/<project>/common/...
├── bukkit/                            <- shared platform core; re-exposes api + common via `api`
│   └── src/main/java/<group>/<project>/bukkit/...
├── platforms/                         <- container directory; NO build.gradle of its own
│   ├── engine/                        <- universal shaded entry point; bundles everything
│   │   └── src/main/resources/plugin.yml   <- templated with ${name}, ${version}
│   ├── spigotmc/                      <- SpigotMC entry point; bundled into engine jar
│   ├── papermc/                       <- PaperMC entry point; bundled into engine jar
│   └── foliamc/                       <- Folia entry point; bundled into engine jar
└── wiki/                              <- user-facing documentation (indexed by wiki/INDEX.md)
```

Rules:
- `platforms/` is a Gradle container project, not a real module. It has **no** `build.gradle`. It is created implicitly by `include 'platforms:spigotmc'` etc. in `settings.gradle`. It is silently skipped by the build — do not put a build file in it.
- Every real module (`api`, `common`, `bukkit`, `platforms:*`) has its own `build.gradle` and its own `src/main/java/...` tree.
- All packages live under one group id, e.g. `io.gitlab.<your-group>.<project>`, with one subpackage per module (`api`, `common`, `bukkit`, `spigotmc`, ...).

## 1. gradle-wrapper.properties

Create `gradle/wrapper/gradle-wrapper.properties`:

```properties
distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-9.5.0-bin.zip
networkTimeout=10000
retries=0
retryBackOffMs=500
validateDistributionUrl=true
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists
```

Also ship `gradlew` and `gradlew.bat` (generated by `gradle wrapper`).

## 2. gradle.properties

Create `gradle.properties` at the root. This drives project identity, versioning, and build behavior:

```properties
# --- Build behavior ---
org.gradle.configuration-cache=true
org.gradle.parallel=true
org.gradle.caching=true

# --- Project identity ---
project-group=io.gitlab.<your-group>
git-org-name=<YourGroup>
git-repository=<your-repo>

# --- Versioning ---
# Do not change project-version without explicit approval (it is a release claim).
project-version=1.0.0
```

`group` and `version` are read by the root `build.gradle` via `project.group` and `project.version`. The `git-*` values are used by publishing/release tooling.

## 3. settings.gradle

Create `settings.gradle` at the root. It declares the root project name and every subproject, including the `platforms:*` container entries.

```groovy
/*
 * settings.gradle — declare every Gradle project in the build.
 */

pluginManagement {
    repositories {
        gradlePluginPortal()
        // The convention plugin hosted on GitLab Maven
        maven {
            name = 'GitLabMaven'
            url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-convention-plugin-project>/packages/maven'
            credentials {
                username = System.getenv('GITLAB_USER')          // or 'gitlab-ci-token'
                password = System.getenv('GITLAB_TOKEN')         // personal access token or CI job token
            }
            authentication {
                basic(BasicAuthentication)
            }
        }
    }
}

plugins {
    // Automatic JDK toolchain resolution
    id 'org.gradle.toolchains.foojay-resolver-convention' version '1.0.0'
}

rootProject.name = '<your-repo>'

include 'api'
include 'common'
include 'bukkit'
include 'platforms:spigotmc'
include 'platforms:papermc'
include 'platforms:foliamc'
include 'platforms:engine'
```

Key points:
- `include 'platforms:spigotmc'` creates two Gradle projects: `platforms` (implicit container, no build file) and `platforms:spigotmc` (real module).
- Do **not** `include 'tools'` unless you have a tools module; the scaffold omits it per the user's request.
- The convention plugin `io.github.mcengine.build-logic` is resolved from **gradlePluginPortal()** (no authentication needed since it was published to the Gradle Plugin Portal). Publishing your own artifacts to GitLab Maven still needs `GITLAB_USER` / `GITLAB_TOKEN` (use `gitlab-ci-token` for CI jobs).

## 4. Root build.gradle

Create `build.gradle` at the root. It applies shared build logic (group, version, Java toolchain, UTF-8, Shadow, Maven publishing, GitLab Maven) and sets project-specific overrides.

```groovy
// Root build.gradle — shared conventions. Only deviations from the convention
// plugin defaults are set here.

plugins {
    id 'io.github.mcengine.build-logic' version '0.1.2'
}

mcengineBuild {
    pomUrl = 'https://<your-org>.gitlab.io/<website>'
}
```

If you are not using a convention plugin, the root `build.gradle` must declare directly:

- `group = project-group` from `gradle.properties`
- `version = project-version` from `gradle.properties`
- Java toolchain (e.g. Java 25) via `java { toolchain { languageVersion = JavaLanguageVersion.of(25) } }`
- UTF-8 encoding for compile tasks
- Shadow plugin configuration
- Maven publishing + GitLab Maven credentials

## 5. Leaf module build.gradle — `api/`

`api` is a pure-Java contract library. It depends on nothing and is published.

`api/build.gradle`:

```groovy
plugins {
    id 'java-library'
}

base {
    archivesName = "${rootProject.name}-api"
}

publishing {
    publications {
        mavenJava(MavenPublication) {
            from components.java

            pom {
                name = "${rootProject.name}-api"
                description = "<Project> API"
            }
        }
    }
}

repositories {
    maven {
        name = 'GitLabMaven'
        url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-repo>/packages/maven'
        credentials {
            username = System.getenv('GITLAB_USER')
            password = System.getenv('GITLAB_TOKEN')
        }
        authentication {
            basic(BasicAuthentication)
        }
    }
}
```

Notes:
- `java-library` exposes `api` and `implementation` configurations; consumers see `api` dependencies transitively.
- `archivesName` controls the published artifact name.
- No Minecraft APIs may appear here — this keeps the data layer unit-testable without a server.
- Publishing repository points at the GitLab Maven endpoint for this project.

## 6. Data layer build.gradle — `common/`

`common` compiles against `api` contracts but must not drag `api` into every consumer of the shaded jar, so it uses `compileOnly`.

`common/build.gradle`:

```groovy
plugins {
    id 'java-library'
}

dependencies {
    compileOnly project(':api')

    // Example external libraries (adjust to your project)
    compileOnly 'com.google.code.gson:gson:2.13.1'

    // Test-only dependencies
    testImplementation project(':api')
    testImplementation 'com.google.code.gson:gson:2.13.1'
    testImplementation 'org.junit.jupiter:junit-jupiter-api:6.1.0'
    testRuntimeOnly 'org.junit.jupiter:junit-jupiter-engine:6.1.0'

    testImplementation 'org.mockito:mockito-core:5.23.0'
    testImplementation 'org.mockito:mockito-junit-jupiter:5.23.0'

    useJUnitPlatform()

    archivesName = "${rootProject.name}-common"

publishing {
    publications {
        mavenJava(MavenPublication) {
            from components.java

            pom {
                name = "${rootProject.name}-common"
                description = "<Project> Common"
            }
```

## 7. Shared platform core build.gradle — `bukkit/`

`bukkit` is the bridge between pure-Java layers and the Minecraft server APIs. It is the **only** module that re-exposes its siblings (`api`, `common`) with `api`, so consumers get those contracts on their own compile classpath.

`bukkit/build.gradle`:

```groovy
import org.gradle.api.tasks.PathSensitivity

plugins {
    id 'java-library'
}

repositories {
    maven {
        name = 'spigotmc-repo'
        url = 'https://hub.spigotmc.org/nexus/content/repositories/snapshots/'
    }
    maven {
        name = 'sonatype'
        url = 'https://oss.sonatype.org/content/repositories/snapshots'
    }
    maven {
        name = 'GitLabMaven'
        url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-repo>/packages/maven'
        credentials {
            username = System.getenv('GITLAB_USER')
            password = System.getenv('GITLAB_TOKEN')
        }
        authentication {
            basic(BasicAuthentication)
        }
    }
}

dependencies {
    // Re-expose contracts so consumers (platform modules) compile against them.
    api project(':api')
    api project(':common')

    // MCAgents-style tool definitions: compileOnly so the published bukkit
    // library never names an unpublished module; the engine bundles the classes.
    compileOnly project(':tools')   // omit if you have no tools module

    // Server API (chosen per project: Spigot, Paper, or Folia).
    compileOnly 'org.spigotmc:spigot-api:26.3-R0.1-SNAPSHOT'

    // JetBrains annotations (Spigot declares them as `provided`, so they are
    // not on the compile classpath through spigot-api).
    compileOnly 'org.jetbrains:annotations:26.1.0'

    testImplementation 'org.spigotmc:spigot-api:26.3-R0.1-SNAPSHOT'
    testImplementation 'org.junit.jupiter:junit-jupiter-api:6.1.0'
    testRuntimeOnly 'org.junit.jupiter:junit-jupiter-engine:6.1.0'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}

test {
    useJUnitPlatform()
}

base {
    archivesName = "${rootProject.name}-bukkit"
}

publishing {
    publications {
        mavenJava(MavenPublication) {
            from components.java

            pom {
                name = "${rootProject.name}-bukkit"
                description = "<Project> Bukkit"
            }
        }
    }
}

repositories {
    maven {
        name = 'GitLabMaven'
        url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-repo>/packages/maven'
        credentials {
            username = System.getenv('GITLAB_USER')
            password = System.getenv('GITLAB_TOKEN')
        }
        authentication {
            basic(BasicAuthentication)
        }
    }
}
```

Key scoping rules for `bukkit`:
- `api project(':api')` and `api project(':common')` — re-expose; consumers need them.
- `compileOnly project(':tools')` — do not drag unpublished modules into published consumers.
- `compileOnly` server API — the server provides it at runtime; never shade it into bukkit.

## 8. Platform module build.gradle — `platforms/spigotmc/`, `platforms/papermc/`, `platforms/foliamc/`

These three modules are **not distributed**. Each exists so the universal engine jar can carry every scheduler/platform implementation and pick the right one at runtime. Each declares its siblings `compileOnly` and ships only its own classes, so the engine's shadowing produces exactly one copy of everything.

### Common template (apply to all three)

`platforms/<platform>/build.gradle`:

```groovy
plugins {
    id 'com.gradleup.shadow'
}

repositories {
    maven {
        name = '<platform-repo>'
        url = '<platform-maven-url>'   // e.g. repo.papermc.io or hub.spigotmc.org
    }
    maven {
        name = 'GitLabMaven'
        url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-repo>/packages/maven'
        credentials {
            username = System.getenv('GITLAB_USER')
            password = System.getenv('GITLAB_TOKEN')
        }
        authentication {
            basic(BasicAuthentication)
        }
    }
}

dependencies {
    // Siblings are compileOnly: they are shaded once by the engine jar.
    // Declaring them implementation/api here would duplicate every class in the final jar.
    compileOnly project(':api')
    compileOnly project(':common')
    compileOnly project(':bukkit')

    // Database drivers: compileOnly, downloaded at runtime via plugin.yml `libraries:`.
    compileOnly 'org.postgresql:postgresql:42.7.11'
    compileOnly 'org.mongodb:mongodb-driver-sync:5.7.0'

    // Platform-specific server API (pick ONE per module; they are mutually exclusive):
    //   SpigotMC:  compileOnly 'org.spigotmc:spigot-api:26.3-R0.1-SNAPSHOT'
    //   PaperMC:   compileOnly 'io.papermc.paper:paper-api:26.3.build.+'
    //   FoliaMC:   compileOnly 'dev.folia:folia-api:26.3.build.5-alpha'
    compileOnly '<platform-api-dependency>'

    // compileOnly does NOT reach the test classpath; bukkit re-exposes api+common,
    // so add it back explicitly for tests.
    testImplementation project(':bukkit')
    testImplementation '<platform-api-dependency>'
    testImplementation 'org.junit.jupiter:junit-jupiter-api:6.1.0'
    testRuntimeOnly 'org.junit.jupiter:junit-jupiter-engine:6.1.0'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
    testImplementation 'org.mockito:mockito-core:5.23.0'
}

test {
    useJUnitPlatform()
}

jar {
    enabled = false   // platform modules ship only via the engine shadowJar
}

shadowJar {
    archiveClassifier.set('')
    mergeServiceFiles()
    configurations = [project.configurations.runtimeClasspath]
}

processResources {
    def props = [
        version: project.version,
        group: project.group,
        name: '<ProjectName>'
    ]
    inputs.properties props
    filteringCharset 'UTF-8'
    filesMatching('plugin.yml') {
        expand props
    }
}

base {
    archivesName = "<ProjectName><Platform>"   // e.g. <ProjectName>SpigotMC
}

build.dependsOn shadowJar
```

### Platform-specific notes

| Module | Server API dependency | Repositories | archivesName |
|--------|----------------------|--------------|--------------|
| `platforms/spigotmc` | `org.spigotmc:spigot-api:26.3-R0.1-SNAPSHOT` | spigotmc-repo, sonatype | `<ProjectName>SpigotMC` |
| `platforms/papermc` | `io.papermc.paper:paper-api:26.3.build.+` | papermc-repo | `<ProjectName>PaperMC` |
| `platforms/foliamc` | `dev.folia:folia-api:26.3.build.5-alpha` | papermc-repo | `<ProjectName>FoliaMC` |

- Folia is a superset of Paper and Spigot APIs (it declares the `org.spigotmc:spigot-api` capability). Declaring all three at once is impossible — Gradle rejects them as a mutually exclusive capability conflict. Platform detection is done at runtime by reflection, so no compile-time Paper or Spigot dependency is required in engine.
- `jar.enabled = false` — the thin jar is disabled; only the shadowJar matters.
- `build.dependsOn shadowJar` — the `build` task produces the shadow jar.

## 9. Universal engine build.gradle — `platforms/engine/`

The engine is the **only distributed artifact**: a single shaded jar that bundles api, common, bukkit, tools, and all three platform modules, plus its own entry point and `plugin.yml`.

`platforms/engine/build.gradle`:

```groovy
plugins {
    id 'com.gradleup.shadow'
}

repositories {
    maven {
        name = "papermc-repo"
        url = "https://repo.papermc.io/repository/maven-public/"
    }
    maven {
        name = "spigotmc-repo"
        url = "https://hub.spigotmc.org/nexus/content/repositories/snapshots/"
    }
    maven {
        name = "sonatype"
        url = "https://oss.sonatype.org/content/repositories/snapshots"
    }
    maven {
        name = 'GitLabMaven'
        url = 'https://gitlab.com/api/v4/projects/<your-group>/<your-repo>/packages/maven'
        credentials {
            username = System.getenv('GITLAB_USER')
            password = System.getenv('GITLAB_TOKEN')
        }
        authentication {
            basic(BasicAuthentication)
        }
    }
}

dependencies {
    // The engine is the shaded artifact: implementation on all seven modules.
    implementation project(':api')
    implementation project(':common')
    implementation project(':bukkit')
    implementation project(':tools')          // omit if no tools module

    // Bundle all three platform modules so the universal jar carries every
    // scheduler implementation and picks the right one at runtime.
    implementation project(':platforms:spigotmc')
    implementation project(':platforms:papermc')
    implementation project(':platforms:foliamc')

    // Database drivers not bundled by the server: compileOnly, downloaded at
    // runtime via plugin.yml `libraries:`. SQLite and MySQL ship with
    // Spigot/Paper, so only PostgreSQL and MongoDB are listed here.
    compileOnly 'org.postgresql:postgresql:42.7.11'
    compileOnly 'org.mongodb:mongodb-driver-sync:5.7.0'

    // Compile against Folia API only (superset of Paper+Spigot).
    compileOnly 'dev.folia:folia-api:26.3.build.5-alpha'
}

// Captured at configuration time so the plugin.yml exclusion rule stays
// configuration-cache friendly (closes over a plain String, not the project).
def ownResourcesDir = sourceSets.main.output.resourcesDir.absolutePath

jar {
    enabled = false
}

// The three platform shadowJars must exist before engine compiles against
// them and bundles them, so wire ordering explicitly.
['spigotmc', 'papermc', 'foliamc'].each { platform ->
    tasks.named('compileJava') { dependsOn ":platforms:${platform}:shadowJar" }
    tasks.named('shadowJar') { dependsOn ":platforms:${platform}:shadowJar" }
}

shadowJar {
    archiveClassifier.set('')
    mergeServiceFiles()

    // Shadow every implementation dependency.
    configurations = [project.configurations.runtimeClasspath]

    // Each bundled platform jar ships its own plugin.yml. Keep only the
    // engine's descriptor (emitted into this module's own resources output)
    // and exclude every copy pulled in from a dependency jar.
    filesMatching('plugin.yml') {
        if (!it.file.absolutePath.startsWith(ownResourcesDir)) {
            it.exclude()
        }
    }
}

processResources {
    def props = [
        version: project.version,
        group: project.group,
        name: '<ProjectName>'
    ]
    inputs.properties props
    filteringCharset 'UTF-8'
    filesMatching('plugin.yml') {
        expand props
    }
}

base {
    archivesName = "<ProjectName>"
}

build.dependsOn shadowJar

tasks.register('exportJar') {
    dependsOn shadowJar

    def exportPath = System.getenv("ENGINE_PLUGIN_JAR_PATH")
    def projectName = rootProject.name
    def shadowJarFile = shadowJar.archiveFile
    def rootBuildDir = rootProject.layout.buildDirectory.get().asFile

    doLast {
        if (!rootBuildDir.exists()) {
            rootBuildDir.mkdirs()
        }
        def sourceFile = shadowJarFile.get().asFile
        def rootTargetFile = new File(rootBuildDir, sourceFile.name)

        java.nio.file.Files.copy(
            sourceFile.toPath(),
            rootTargetFile.toPath(),
            java.nio.file.StandardCopyOption.REPLACE_EXISTING
        )
        println "Exported ${sourceFile.name} to root build directory"

        if (exportPath != null && !exportPath.isEmpty()) {
            def destDir = new File(exportPath)
            if (destDir.exists() && destDir.isDirectory()) {
                destDir.listFiles().each { f ->
                    if (f.name.startsWith(projectName) && f.name.endsWith(".jar")) {
                        println "Deleting existing plugin jar: ${f.name}"
                        f.delete()
                    }
                }
                def targetFile = new File(destDir, sourceFile.name)
                java.nio.file.Files.copy(
                    sourceFile.toPath(),
                    targetFile.toPath(),
                    java.nio.file.StandardCopyOption.REPLACE_EXISTING
                )
                println "Exported ${sourceFile.name} to ${exportPath}"
            } else {
                println "Export path does not exist or is not a directory: ${exportPath}"
            }
        }
    }
}

build.finalizedBy exportJar
```

Engine-specific rules:
- `implementation` on all seven modules — engine is the one place classes actually belong.
- `compileOnly` Folia API — provides Bukkit/Paper/Folia types for the bundled schedulers; platform detection is runtime reflection.
- `compileOnly` PostgreSQL + MongoDB drivers — downloaded by the server at runtime via `plugin.yml` `libraries:`.
- `platforms/*:shadowJar` is an explicit `dependsOn` of engine's `compileJava` and `shadowJar` because Gradle task heuristics alone do not order cross-module shadowing reliably.
- `filesMatching('plugin.yml')` excludes every `plugin.yml` from dependency jars, keeping only engine's own descriptor so the universal jar carries a single authoritative `plugin.yml`.
- `archiveClassifier.set('')` — the shadow jar uses the plain artifact name (no classifier).
- `mergeServiceFiles()` — merges `META-INF/services/*` from all dependencies.

## 10. plugin.yml template (engine and each platform)

Each module with a `plugin.yml` uses Gradle resource filtering (`processResources` with `expand props`). The file contains placeholder tokens replaced at build time:

```yaml
name: ${name}
version: ${version}
main: <group>.<project>.<module>.MainClass
commands:
  <command>:
    description: <description>
    usage: /<command> <args>
api-version: '1.20'
folia-supported: true          // engine only; platform modules omit
softdepend:
  - MCAgents
author: <YourGroup>
description: <one-line description>

libraries:
  - com.google.code.gson:gson:2.13.1
  - org.postgresql:postgresql:42.7.11
  - org.mongodb:mongodb-driver-sync:5.7.0

permissions:
  <group>.<project>.*:
    description: Grants every command
    default: op
    children:
      ...
```

`processResources` expands `${name}`, `${version}`, `${group}` from the `props` map in each module's `build.gradle`. The `main` class differs per module:
- engine: `<group>.<project>.engine.<ProjectName>EnginePlugin`
- spigotmc: `<group>.<project>.spigotmc.<ProjectName>Plugin`
- papermc: `<group>.<project>.papermc.<ProjectName>Plugin`
- foliamc: `<group>.<project>.foliamc.<ProjectName>Plugin`

## 11. Dependency scoping rules (load-bearing)

The dependency direction is one-way:

```
api  ←  common  ←  bukkit  ←  platforms:{spigotmc, papermc, foliamc}  ←  platforms:engine
                         ↑
                       tools
```

| Module | Sibling scoping | Why |
|--------|----------------|-----|
| `api` | — (leaf) | Pure Java contracts; published library; depends on nothing. |
| `common` | `compileOnly project(':api')` | Compiles against contracts but never drags `api` into consumers of the shaded jar. |
| `tools` | — (leaf) | Pure Java; omitted from this scaffold if unused. |
| `bukkit` | `api project(':api')`, `api project(':common')`, `compileOnly project(':tools')` | Only module that re-exposes; consumers need contracts on their compile classpath. |
| `platforms:*` | `compileOnly` on api, common, bukkit | Bundled into engine; `implementation`/`api` would duplicate every class in the final jar. |
| `platforms:engine` | `implementation` on all seven | The shaded artifact; the one place classes belong. |

Consequences:
- `compileOnly` does **not** reach the test classpath. Every platform module adds `testImplementation project(':bukkit')` explicitly because bukkit re-exposes api and common.
- Promoting any platform module to `api` or `implementation` inside engine duplicates the whole core inside the final jar.

## 12. Build commands

From the repo root:

```bash
# Compile every module and run tests
./gradlew build

# Build only the universal shaded jar
./gradlew :platforms:engine:shadowJar

# Export the jar to the local test server (if ENGINE_PLUGIN_JAR_PATH is set)
./gradlew :platforms:engine:exportJar
```

The resulting shaded jar is dropped into the server's `plugins/` directory. The default storage backend (SQLite) needs no configuration.
